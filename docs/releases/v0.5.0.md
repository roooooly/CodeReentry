# CodeReentry 0.5.0 Source Beta

CodeReentry 0.5.0 makes the project-to-session recovery loop inspectable before the app
touches a user's local project or session data. It also adds native GitHub Copilot CLI
session recovery and documents the complete scan, inspect, and continue path.

## Try the isolated demo

This remains a **source beta**. No binary is attached because the project does not yet
have a Developer ID signed and Apple-notarized public build. Do not install binaries
from unofficial mirrors.

Requirements: macOS 14 or newer and Xcode with Swift 6 support.

```bash
git clone --branch v0.5.0 https://github.com/roooooly/CodeReentry.git
cd CodeReentry
./scripts/run-source.sh --demo
```

Demo mode uses an in-memory database plus synthetic projects, conversations, memory,
and subscription costs under a disposable temporary directory. It does not read local
session stores, scan local usage files, start plugins or MCP servers, run Git commands,
launch developer tools, or write to the normal CodeReentry database and preferences.
The temporary workspace is removed when the app exits.

To build and launch the normal source beta instead, run:

```bash
./scripts/run-source.sh
```

## GitHub Copilot CLI recovery

- Discover project-scoped sessions from documented `session-state` events.
- Read only persisted root-agent messages and project-context events.
- Exclude reasoning, system prompts, streaming deltas, subagent events, and symbolic
  links from discovery and conversation loading.
- Bound directory, file, byte, line, message, and character work.
- Resume the exact discovered session with `copilot --resume <full-session-id>` while
  honoring the saved executable and environment.

The implementation contract and pinned official sources are recorded in the
[GitHub Copilot CLI compatibility note](../github-copilot-cli-compatibility.md). Tests
contain only synthetic sessions derived from the documented format.

## Verification boundary

The release is tagged only after the main branch passes the one-command source build,
DevHubCore tests, synthetic performance gates, English and Simplified Chinese app tests,
repository privacy audit, and re-entry-recorder tests.

Engineering tests are not presented as real-user evidence. The recovery hypothesis still
requires privacy-safe real attempts, and public binary distribution remains blocked on
Developer ID signing, notarization, Gatekeeper verification, and a clean-Mac installation
check.
